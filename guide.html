Prototype guide

How to view, navigate and test this prototype. Written for reviewers and markers of the 505IT HCI and Web Development assessment.

1. Viewing the prototype

The prototype is a static website. It needs no installation, account or database.

  1. Easiest: open the file

    Unzip the folder and double-click index.html. It opens in your web browser and every page and feature works.

  2. Alternative: run a local web server

    In the project folder run python -m http.server 5500, then go to http://localhost:5500.

  3. Check different devices

    Resize the browser window, or open developer tools (F12) and use device mode to view phone and tablet sizes.

Works in current versions of Chrome, Edge, Firefox and Safari. An internet connection is only needed for the web fonts; without it the site falls back to system fonts.

3. Things to try

  1. Book a place on an event

    Choose "Book a place" or a "Book" button on the Events page. Try "Continue" without filling anything in to see the error handling, then complete all 4 steps. Use a "Change" link on the review step to go back and edit an answer.

  2. Find a service

    On Services, type "walk" or "debt" in the search box, or open a topic. Use ↑ and ↓ to move between topic headings.

  3. Browse events by date

    On Events, pick a date with a dot on the calendar, then filter by a topic such as Physical activity.

  4. Use the homepage slider

    Use the arrows or the lines to change slides, and the pause button to stop it moving.

  5. Read a success story

    Open a story from the homepage carousel or the News page. Press Esc to close it.

  6. Send a message

    On Contact, choose "Yes, please call me" to see the phone number field appear, then submit the form.

4. Testing accessibility

  • Keyboard only: press Tab from the top of any page. The first stop is "Skip to main content". Everything can be used without a mouse.
  • Text size and contrast: open "Text size" in the header to make the text larger or turn on high contrast. Your choice is remembered on every page.
  • Zoom: zoom the browser to 200%. The layout reflows without sideways scrolling.
  • Reduced motion: turn on "reduce motion" in your operating system. The slider then stops moving by itself and animations are switched off.
  • Screen reader: try NVDA (Windows) or VoiceOver (Mac). Headings, landmarks, form errors and the booking steps are announced. Slide changes are announced once the slider is paused, so they don't interrupt reading.

5. Technology used

  • HTML5: semantic elements, landmarks and native <dialog> and <details>
  • CSS3: custom properties (design tokens), Grid, Flexbox, media queries, prefers-reduced-motion
  • JavaScript (ES6): no frameworks or libraries; separate scripts for shared features, the directory, calendar, booking wizard and sliders
  • WAI-ARIA: accordion, carousel, dialog and switch patterns from the W3C Authoring Practices Guide
  • Testing: axe-core accessibility engine, browser device emulation, keyboard testing

Folder structure

  • *.html: one file per page
  • css/style.css: all styles and design tokens
  • js/: data.js (sample content), main.js (shared), plus a script per feature
  • images/: photographs, with sources in images/CREDITS.md

6. Prototype limitations

  • There is no server or database. Bookings and messages show a confirmation but are not saved or emailed, and places left reset when the page is reloaded.
  • Event dates are generated relative to today, so the calendar always shows upcoming events.
  • The Hub, its staff, residents' names and stories are fictional. Photographs are licensed stock images from Unsplash and do not show real Hub users.
  • The map on the Contact page is a placeholder.

A production version would add a booking database, email confirmations, a content management system for news and events, and accounts for managing bookings.

UI design options

Three distinct interface concepts explored during the design phase, shown as low-fidelity wireframes for desktop and mobile. Option C was selected and implemented in this prototype.

Option A: Card grid Option B: Text-first tabs Option C: Guided hybrid (chosen) Comparison

Option A: Visual card grid

A highly visual, image-led layout in which every content type (services, events, news) is a card in a responsive grid. Horizontal navigation on desktop collapses to a bottom tab bar on mobile. Booking is a single long form on one page.

Strengths

  • Visually engaging; scannable at a glance (Gestalt proximity and similarity).
  • Cards reflow naturally across breakpoints.
  • Familiar pattern from popular apps.

Weaknesses

  • 16+ cards on one screen increases cognitive load (Hick's Law).
  • Image-heavy: slower on low-bandwidth connections, relies on good alt text.
  • Long single-page form is daunting for low-confidence users, and errors are found late.

Option B: Text-first with tabs

A minimal, GOV.UK-inspired design: plain text links, generous whitespace and no imagery. Services are grouped in horizontal tabs, events are a simple chronological list, and booking is a single form. Navigation is a text list that wraps on mobile.

Strengths

  • Very fast, lightweight and highly accessible by default.
  • Clear typographic hierarchy, suits screen readers and low literacy.
  • Easy to maintain.

Weaknesses

  • Tabs with 6 categories overflow on mobile and hide content.
  • Feels institutional, which may discourage people with low motivation (e.g. low mood).
  • No visual date overview: hard to see "what's on this week".

Option C: Guided hybrid Selected and implemented

Combines patterns where each works best: cards on the homepage for browsing, an accordion service directory with search, a calendar date-picker alongside an event list, a multi-step wizard for booking, a task-based "I want to…" panel and a hamburger menu on mobile. The homepage opens with an image slider (with pause, previous and next controls) and uses real photography throughout to make the Hub feel warm and human. A "Display" menu in the header offers larger text and high contrast.

Strengths

  • Progressive disclosure (accordion, wizard) reduces cognitive load for low digital literacy users.
  • Calendar gives a visual overview and a list provides an accessible alternative.
  • Wizard validates each step, so errors are caught early and the error summary links to each field (Nielsen: error prevention and recovery).
  • Topics are written as people's needs, and the homepage leads with what is happening soon, which matches how residents think rather than how the council is organised.

Weaknesses / mitigations

  • More complex to build and test. Mitigated with WAI-ARIA patterns and keyboard support.
  • Hamburger hides navigation on mobile. Mitigated by a labelled "Menu" button and key CTAs on the homepage.
  • Wizard adds clicks for expert users. Mitigated with a progress bar and "Change" links on the review step.
